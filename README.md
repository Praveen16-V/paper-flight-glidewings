# Paper Flight

> A paper plane rides gusts of wind through an ever-changing sky — one tap, infinite falls.

Flutter + Flame endless arcade flyer. Portrait orientation, F2P with ads + IAP.

---

## Quick start

```bash
# 1. Install dependencies
flutter pub get

# 2. Run on a connected device / emulator (portrait)
flutter run
```

> **Note:** The project compiles and runs immediately with placeholder assets and
> test ad unit IDs. No Firebase project or store accounts are needed for local dev.

## Pre-release checklist

### Firebase
```bash
# Install flutterfire CLI then:
flutterfire configure
# This overwrites lib/firebase_options.dart with real credentials.
# Also creates android/google-services.json and ios/GoogleService-Info.plist.
```

### AdMob
Replace the test ad unit IDs in `lib/services/ad_service.dart`:
```dart
static String get _rewardedId => Platform.isIOS
    ? 'ca-app-pub-XXXX/YYYY'   // real iOS rewarded ID
    : 'ca-app-pub-XXXX/YYYY';  // real Android rewarded ID

static String get _interstitialId => ...
```

### IAP
Create products in App Store Connect / Google Play Console matching the IDs in
`lib/services/iap_service.dart` → `IapProductIds`.

### Assets
Replace placeholder PNGs/MP3s in `assets/` with real art and audio.
Asset paths are registered in `pubspec.yaml` — add new files there if you
add more.

## Key design decisions

| Decision | Rationale |
|---|---|
| Static camera + downward scroll | Simplest Flame architecture for a vertical scroller — no camera-follow logic |
| Object pools for obstacles/coins | Prevents GC spikes on low-end Android (per GDD §13) |
| Riverpod outside game loop | Currency/unlocks/settings need to survive screen transitions; Flame's component system is enough inside the loop |
| Hand-written Hive adapter | Avoids build_runner complexity for CI; safe to replace with generated adapter later |
| ValueNoise FBM for wind | No external package dependency; deterministic with a seed; cheap enough to sample 4 lanes per frame |
| Test AdMob IDs | Always safe to commit; real IDs belong in a build-flavour env file, not source |

## Tuning

All gameplay constants live in `lib/core/constants/game_config.dart`.
No magic numbers anywhere else — change one value and it propagates everywhere.

Key knobs to adjust during playtesting:
- `baseScrollSpeed` / `scrollAcceleration` — overall difficulty ramp
- `liftForce` / `gravity` — hold/release feel
- `maxWindForce` — wind challenge level
- `obstacleBaseSpawnInterval` / `obstacleMinSpawnInterval` — density curve
- `nearMissCloseShaveDistance` / `nearMissHairThinDistance` / `nearMissDeathDefyingDistance` — tiered near-miss clearance thresholds
- `nearMissCloseShavePoints` / `nearMissHairThinPoints` / `nearMissDeathDefyingPoints` — tier payouts
- `comboDrainDuration` / `comboHitRetentionFraction` — combo decay gauge pace & shield-hit penalty
- `cleanFlightBasePoints` / `thermalSurfBasePoints` — Clean Flight streak payouts
- `interstitialFrequencyCap` — ad cadence (increase to reduce friction)
